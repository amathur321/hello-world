How the map drives your chats

The graph is the source of truth. Sessions bind to nodes. The map both reflects and steers the work.

01
Branch a topic
In any chat, a tangent forks off — Wayfinder spins up a linked session.
02
A star appears
A node is written to the graph and bound to that session by tag.
03
Hit a wall → park
Resume-context + typed blocker are captured before you move on.
04
Resume anywhere
From the map, reopen the exact session with its saved context.
Graph store
Git-tracked node files in graph/ — the versioned, portable source of truth. This is the "never lose a thread" guarantee: every star is a diffable file.
Session binding
Each real session is tagged starmap:<nodeId>. The dashboard maps both ways — node → session and session → node — so a chat and its star stay welded together across Claude Code, Cowork, and claude.ai.
Wayfinder skill
The command layer inside your chats: /wf branch "topic" forks a linked session + node, /wf park snapshots resume-context and the blocker, /wf next recommends an unblocked frontier, /wf resume <id> reopens a session.
Auto-park
When you signal a wall — "I'm stuck", "come back to this", "blocked on…" — the skill proactively offers to park: it captures the next concrete step and the typed blocker before context is lost. In the map, Park is a capture form, not a status flip.
Dashboard
This star map — your command center, with a mobile glance mode that groups threads by what needs you. Phase 1 renders from the committed graph; phase 2 gains live capabilities so branch / park / resume fire straight from a node back into the harness.
Nudges
A weekly routine sweeps for stale frontier stars and surfaces "these three have been waiting on a decision only you can make."
